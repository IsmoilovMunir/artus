# ARTUS — интернет-магазин телевизоров и аксессуаров

Статус: черновик v0.1. Документ описывает предметную область, бизнес-идею и
укрупнённый функционал ДО начала разработки. Базовые вопросы закрыты (см.
раздел 5), часть деталей осознанно отложена на будущие итерации (раздел 6).

---

## 1. Бизнес-идея

**Что это:** интернет-магазин по продаже телевизоров и аксессуаров к ним
(кронштейны, пульты, кабели/переходники, саундбары, антенны и т.п.) для
рынка России.

**Аудитория:**
- **B2C** — розничные покупатели, выбирают 1 ТВ + аксессуары для дома.
- **B2B** — оптовые покупатели работают в том же каталоге и личном кабинете,
  что и розница (отдельного B2B-кабинета/каталога нет). Отличие — объёмная
  скидка: при заказе одного товара от определённого количества (ориентир —
  от 10 шт.) сумма по позиции считается по другой (оптовой) цене. Точные
  пороги количества и оптовые цены/скидки настраиваются позже, при
  наполнении каталога — сама механика (правило "количество → другая цена")
  закладывается в модуль заказов и каталога с самого начала.

**Ценностное предложение:**
- Всегда актуальные цены и остатки — товарные данные подтягиваются из
  МойСклад и обновляются на сайте не реже раза в минуту, риск продать
  несуществующий товар минимален.
- Витрина богаче, чем в МойСклад: сайт дополняет каждую карточку SEO-текстом,
  доп. фото, развёрнутым описанием и характеристиками для фильтров.

**Оплата:** при получении — наличными курьеру (безналичная онлайн-оплата и
интеграция с эквайрингом не предусмотрены в первой версии).

**Доставка:** собственная служба доставки/курьеры (внешние службы доставки и
самовывоз в первой версии не предусмотрены). При оформлении заказа покупатель
просто указывает полный адрес доставки текстом; расчёт зон/тарифов и
согласование деталей доставки в первой версии не автоматизируются — этим
занимаются вручную после получения заказа (менеджер/курьер).

**Источник истины по товарам:** МойСклад. Остаток — всегда read-only на
сайте. Название и цену МойСклад отдаёт только при первом импорте товара;
дальше это поля admin, как и остальной контент карточки.

## 2. Предметная область

### 2.1 Ключевые сущности

| Сущность | Описание | Источник данных |
|---|---|---|
| **Category** (Категория) | Группа товаров (Телевизоры, Кронштейны, Пульты, Кабели, Саундбары, Антенны...) | МойСклад (группа товаров) |
| **Product** (Товар) | Базовые данные: название, артикул, категория, цена, остаток | МойСклад (остаток — постоянно; название/цена — только при первом импорте) |
| **ProductContent** (Карточка товара, доп. данные) | SEO (title/description/slug), развёрнутое описание, доп. фото/галерея, характеристики для фильтров сайта | Сайт (admin) |
| **Attribute / AttributeValue** (Характеристика) | Диагональ, разрешение, Smart TV, бренд, тип матрицы и т.п. | Частично МойСклад (доп. поля), частично сайт |
| **Stock** (Остаток) | Количество товара на складе | МойСклад (всегда, каждая синхронизация) |
| **Price** (Цена) | Розничная цена + правило объёмной скидки (кол-во → другая цена за позицию) | МойСклад — только при первом импорте товара, дальше редактируется в admin; правило скидки — сайт |
| **Customer** (Покупатель) | Зарегистрированный пользователь сайта: контакты, адреса, история заказов | Сайт |
| **Order** (Заказ) | Заказ, оформленный на сайте: позиции, сумма, адрес доставки (вводится текстом целиком), статус | Сайт (в МойСклад не выгружается) |
| **OrderItem** (Позиция заказа) | Товар + количество + цена на момент заказа | Сайт |
| **OrderStatus** (Статус заказа) | Новый → Подтверждён → В доставке → Доставлен / Отменён | Сайт |
| **Courier** (Курьер) | Сотрудник, назначаемый на доставку заказа | Сайт (admin) |
| **Review** (Отзыв) | Отзыв и рейтинг покупателя к товару, требует модерации | Сайт |
| **Favorite** (Избранное) | Список избранных товаров покупателя | Сайт |
| **ComparisonList** (Сравнение) | Список товаров для сравнения характеристик | Сайт |
| **Promotion / PromoCode** (Акция/промокод) | Скидки, сезонные акции | Сайт (admin) |
| **ContentPage / Banner** (Контент) | Статические страницы, баннеры на главной | Сайт (admin) |
| **AdminUser / Role** (Пользователь админки) | Менеджер, оператор склада, курьер, супер-админ | Сайт (admin) |

### 2.2 Принцип разделения ответственности

- **МойСклад** — единственный источник правды по остатку (всегда) и по
  названию/цене/артикулу/категории **только в момент первого импорта**
  товара.
- **Сайт (backend + admin)** — источник правды по: SEO, медиаконтенту,
  расширенному описанию, заказам, покупателям, отзывам, акциям, контенту, а
  также по названию и цене после того, как товар был впервые импортирован.
- Admin **не редактирует остаток** — это поле всегда read-only и приходит
  только из МойСклад. Название и цену admin может редактировать сразу после
  того, как товар появился в каталоге (МойСклад их больше не перезаписывает).

### 2.3 Синхронизация с МойСклад

- **Направление:** одностороннее, МойСклад → Сайт. Обратно в МойСклад ничего
  не уходит: заказы, оформленные на сайте, обрабатываются только в
  бэкенде/админке сайта (в МойСклад не создаются).
- **Периодичность:** не реже раза в минуту — изменения в МойСклад (новая
  цена, изменившийся остаток, новый товар) должны отражаться на сайте в
  течение ~1 минуты.
- **Что синхронизируется:** товары, остатки, цены, категории.
- **Склад:** в МойСклад один склад — остаток синхронизируется без разбивки
  по точкам/складам.
- **Авторизация:** доступ к МойСклад JSON API — по API-токену (long-lived
  token, без OAuth2-флоу).
- **Технически (к проработке в infra/backend):** периодический опрос
  МойСклад JSON API (`/entity/product`, `/entity/productfolder`,
  `/report/stock/all` и т.п.) планировщиком (scheduler) с интервалом в 1
  минуту; сравнение по `updated`/version для минимизации нагрузки. Поддержка
  МойСклад webhooks на тарифе не подтверждена — синхронизация строится на
  polling, к вебхукам можно будет перейти позже как к оптимизации.

## 3. Роли пользователей

| Роль | Доступ |
|---|---|
| Гость | Просмотр каталога, карточек, сравнение, поиск |
| Покупатель (B2C) | + личный кабинет, история заказов, избранное, отзывы, оформление заказа |
| Покупатель (B2B) | Тот же каталог/кабинет, что и B2C; при заказе от порогового кол-ва одного товара применяется оптовая цена |
| Менеджер (admin) | Управление заказами и статусами, дополнение карточек товара |
| Оператор контента (admin) | Управление контентом сайта: баннеры, акции, страницы |
| Курьер (admin, ограниченно) | Просмотр назначенных заказов, смена статуса доставки |
| Супер-админ | Управление пользователями/ролями админки + всё вышеперечисленное |

## 4. Функционал (укрупнённо)

### 4.1 Публичный сайт (frontend)
- Каталог с категориями (Телевизоры, Кронштейны, Пульты, Кабели/переходники,
  Саундбары, Антенны и т.д.)
- Карточка товара: фото, характеристики, цена, наличие, отзывы/рейтинг
- Поиск и фильтры по характеристикам (бренд, диагональ, разрешение, Smart TV,
  цена, наличие на складе)
- Личный кабинет: регистрация/вход, история и статус заказов
- Избранное
- Сравнение товаров по характеристикам
- Отзывы и рейтинги товаров
- Акции/промокоды/скидки *(отложено на после MVP)*
- Корзина и оформление заказа: адрес доставки вводится текстом целиком,
  оплата при получении, доставка курьером; email-уведомления о статусе
  заказа

### 4.2 Админка (admin)
- Просмотр каталога, синхронизированного из МойСклад (остаток — всегда
  read-only; название и цена — read-only только до первого редактирования
  admin'ом)
- Дополнение карточки товара: SEO, доп. фото/галерея, описание,
  характеристики для фильтров, а также название и цена
- Управление заказами: список, детали, смена статуса, назначение курьера
- Управление контентом сайта: баннеры, акции, промокоды, статические страницы
- Модерация отзывов
- Управление пользователями и ролями админки (RBAC)

### 4.3 Backend (Spring Java)
- REST API для frontend и admin (раздельная аутентификация/JWT для
  покупателей и админов)
- Модуль интеграции с МойСклад: планировщик синхронизации (раз в минуту),
  сопоставление категорий/товаров/остатков/цен с локальной БД
- Модуль каталога: локальный кэш товарных данных МойСклад + доп. контент сайта
- Модуль заказов: создание, статусная модель, история
- Модуль пользователей: покупатели + админ-пользователи с ролями
- Модуль контента: баннеры, акции, промокоды, страницы
- Модуль отзывов и модерации

### 4.4 Инфраструктура (infra)
- CI/CD: GitHub (репозиторий + GitHub Actions) для авто-развёртывания
  admin/frontend/backend
- Хостинг: сервер/облако — ориентир Timeweb (уточняется при переходе к
  инфраструктуре)
- Контейнеризация (Docker) для всех сервисов
- Окружения: dev / staging / prod
- Хранение секретов (API-токен МойСклад и т.п.)
- Уведомления покупателю о статусе заказа — по email
- Логирование и мониторинг (в т.ч. синхронизации с МойСклад — алерты при
  сбое интеграции)

## 5. Решённые вопросы (v0.1)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Характеристики/фильтры по категориям | Нужны (подтверждено). Точный набор атрибутов по каждой категории (ТВ, кронштейны, пульты и т.д.) определяется позже, при наполнении каталога — модель `Attribute/AttributeValue` в БД закладывается сразу, чтобы список полей можно было расширять без миграций логики. |
| 2 | B2B-условия | Отдельного B2B-кабинета/каталога нет — тот же сайт, что и для розницы. Правило объёмной скидки: заказ одного товара от порогового количества (ориентир 10 шт.) считается по другой (оптовой) цене за позицию. Конкретные пороги и оптовые цены настраиваются позже, но саму механику закладываем в модуль заказов с начала разработки. |
| 3 | Доставка | Без зон/тарифов и авторасчёта стоимости в первой версии. Покупатель при оформлении заказа просто указывает полный адрес доставки текстом; согласование деталей доставки — вручную, после получения заказа. |
| 4 | Уведомления | Email-уведомления о статусе заказа — достаточно для первой версии. SMS/Telegram не нужны. |
| 5 | Склад(ы) | Один склад в МойСклад, разбивка остатков по точкам не требуется. |
| 6 | МойСклад: webhooks vs polling | Авторизация к API — по токену. Поддержка вебхуков на тарифе не подтверждена, поэтому синхронизация строится на периодическом polling (раз в минуту) — это уже соответствует требованию по SLA обновления данных. |
| 7 | Хостинг/CI-CD | CI/CD — через GitHub (репозиторий + GitHub Actions). Хостинг — ориентировочно Timeweb; уточняется при переходе к проработке infra. |
| 8 | Промокоды/акции | Функционал реализуется позже, не входит в MVP. Модель `Promotion/PromoCode` остаётся в предметной области как задел на будущее, но в первую итерацию разработки не включается. |

## 6. Отложено на будущие итерации (не MVP)

- Точный список характеристик/фильтров по каждой категории товара.
- Конкретные пороги количества и оптовые цены для объёмной скидки.
- Промокоды, акции, сезонные скидки (кроме уже заложенной объёмной скидки).
- Возможный переход с polling на МойСклад webhooks, если тариф это позволит.
- Уточнение конкретного сервера/тарифа Timeweb (или альтернативы) для хостинга.
